本板块收录「星际枢纽」在导入、安装与分发内容时依赖的约定。它们不是操作步骤，而是被其他文档引用的事实来源：写清单、打包、排查识别失败时，以这里的定义为准。

- [星际枢纽压缩包标准](/reference/scnexus-package)：`package.json` 的字段定义、`Maps` / `Mods` 资源声明、启动器与图片文档的写法，以及校验分几层。
- [CCM 压缩包标准](/reference/ccm-package)：`metadata.txt` 的键值格式、目录布局与安装落点，以及星际枢纽读取这类包时的处理方式。
- [GitHub 安装源标准](/reference/github-source)：把公开仓库当作安装源时，仓库需要满足的清单与结构要求。

## 该看哪一篇

| 你的情况 | 看这里 |
| --- | --- |
| 新做作品，要打一个星际枢纽能直接安装的包 | 星际枢纽压缩包标准 |
| 手上有 CCM 时期的战役包，想知道它会被装到哪里 | CCM 压缩包标准 |
| 想把作品放在 GitHub 上让玩家直接下载 | GitHub 安装源标准，外加清单字段 |
| 只是导入现成的压缩包 | [战役管理](/guide/campaign)、[自制作品](/guide/customize) |

三条标准的关系是并列的：星际枢纽标准是当前的推荐格式，能表达战役、自制作品与共享模组包；CCM 标准是兼容旧作品时读取的格式，只描述战役；GitHub 安装源不是另一种格式，它只是把按星际枢纽标准做好的仓库当作下载来源，所以清单规则完全一致。
